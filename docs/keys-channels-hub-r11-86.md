# 音量键、信道与群聊枢纽修复

版本：固件 r11-86 / APP 1.2.16-heimao（28）。
基础：r11-85 / APP 1.2.15；用户于 2026-11-11 反馈该基础版本测试无问题。
该反馈没有列明设备身份和逐项测量条件，不推断为四台设备均已升级或全部压力测试通过。
本轮生成新的测试候选包，不覆盖 r11-85，不自动刷设备或发射。

## 音量键

按用户的实物反馈，音量加改为 GPIO39，音量减改为 GPIO38。四个可配置功能键的
逻辑索引、NVS 动作映射、短按/长按逻辑及喇叭的 0–4 档保持原有规则。
不清空按键设置。如果之前通过自定义动作补偿过反向，升级后需自行把这两键恢复为
对应的音量加/减；固件无法判断一次自定义映射是否是用户有意更改。

## 信道切换

网页信道库、APP 信道库、实体信道键、桥接信道选择和控制台桥接选择共用一条
带互斥的应用路径。每次选择（包括重选同一信道）完整下发模块参数并核对 ACK；
确认后才同步桥接选择。实体按键和状态接口根据已确认的完整参数匹配当前信道，
不继续使用独立的旧按键游标。重复参数的信道在本次运行中优先保留最后明确选择。

- 桥接开启时，从信道库或实体键应用信道会同步桥接选择。
- 桥接关闭时，普通切信道保留桥接预选；从桥接选择器明确选择仍会立即调谐。
- 切换本地/P2P/MQTT 模式或单独启停桥接，延续 r11-85 的规则：保留当前射频参数。
- 手动修改频率、静噪等参数后，如果不再完整匹配预设，当前信道为 0（自定义）。
  桥接界面同时显示实际 RX/TX，预选信道不会被冒充为实际频率。
- PTT/尾音未释放、模块忙、模块拒绝/超时、存储失败分别返回真实失败结果。
  无模块确认时不宣称切换成功；模块部分配置失败仍沿用原有 RF 阻断保护，不假装已自动回退。
- 网页切换时阻止重复提交，失败后即使选择器仍有焦点，也恢复板端实际选择。
  请求超过 12 秒会释放界面的切换锁并刷新实际状态，不因断网永久停在“切换中”。
- 通话后的空闲配置重下发在模块锁内核对当前配置；旧快照不再覆盖期间新切换的信道。
- 桥接开关/选择的保存失败不会报告已保存；不改变接收滤波、功率政策、PTT 或音频增益。

## Hub 组网规则与地址

推荐单枢纽星型：A 开启“作为群聊枢纽”，B/C 等成员关闭该开关并连接 A；
房间号和密钥保持一致。开启枢纽只允许本机转发已接收的语音，不自动建立任何对端。
最大 16 个槽位、不含本机；已发现的转发成员也占运行表槽位。单枢纽可直接配置
最多 16 个成员；这不增加混音、多人抢话仲裁或全网人数保证。

- 直连节点的地址、原始讲话者身份、经哪个枢纽转发分别记录。
- 经枢纽发现的讲话者显示“经 A 转发 · 无直连地址”，不显示虚构的 0.0.0.0，
  不向它单独发送 KNOCK/PING，不把它当直连配置存进 NVS。后来直接握手可将其提升为直连。
- 转发成员的“最近收到语音”只表示收到过其语音，不是端到端在线状态保证；不展示虚构 RTT。
- 普通对端过期不再误报“枢纽离线”；仅根据已知枢纽的最后实际帧时间判断。
- 枢纽角色随兼容控制帧通告；可从旧枢纽的多来源转发推断其角色，但旧版没有完整角色通告。
- 转发包保留原始讲话者及音频，附加已转发标志。新版不再次转发此包，也不向其他已知枢纽
  继续转发。界面提示多枢纽冲突，不提供多级枢纽拓扑。
- 旧版仍能接收现有音频格式；多枢纽/混用旧枢纽的回环保护不作保证，建议整组使用新版。
- 公网 IPv4 未获得、网络断开、地址超过 30 秒未刷新、IPv6 缺失分别提示。
  本机公网 IPv4 未获得不等于已有 LAN/IPv6 连接失败；网页和 APP 均可重新触发 STUN。
  APP 不提供无效或过期 IPv4 的快捷复制。对端的空地址仅表示等待握手取得地址。
- 本轮没有修改语音编解码、网络到 APP 的音频分流、接收保护、尾音或模拟中继增益。

API 在原 np2p 对象上追加 hub_role / hub_conflict / direct_count / indirect_count，
每行追加 route（direct/hub）、via、hub。peer_count 仍为实际返回的运行表条目数，
旧字段和旧版四槽迁移/v3 配置格式保持兼容。

## 12.5 kHz 步进结论

本版本继续使用已验证的 12.5 kHz 频率网格。步进与 12.5/25 kHz 带宽是独立参数。
固件 sa818_freq.c、网页与 APP 都有网格校验；去掉校验只会允许输入更多数字，
不能证明 SA818S 的内部固件会按这些数值调谐。

原厂 SA818S V1.2 规格书第 6 页要求频率为 12.5/25 kHz 的整数倍，没有提供已确认的
5/6.25 kHz 解锁命令：
https://www.nicerf.cn/uploads/20231124/SA818S%201W%E5%B5%8C%E5%85%A5%E5%BC%8F%E5%B0%8F%E4%BD%93%E7%A7%AF%E5%AF%B9%E8%AE%B2%E6%9C%BA%E6%A8%A1%E5%9D%97V1.2.pdf

若继续实验，应另选明确型号/内部版本的模块与候选步进，保存原配置，在独立实验固件中
发送非网格设置，先验证接收调谐位置；需要确认发射载频时另用仪器和明确的测试条件。
即使模块回复成功，也必须排除内部取整。未完成这些测量前不开放全局“解锁”，本轮未上板执行。

## 本轮验证与用户验收

自动验证范围以候选包 BUILD-INFO.json 和 validation 日志为准。
主机回归直接编译生产信道/桥接与对端函数，网页分别用 DOM 替身和 Chromium 的模拟 HTTP
接口检查；APP 做单测、Lint 与 APK 构建/签名；固件做单 worker 构建和 HTTP 栈上限检查。
这些不替代本轮新版本的实板验收。

用户验收：音量两键短按/长按；网页/APP/实体键交替切换并核对实际频率；同信道重选；
发射结束后的切换；重启设置；三台单枢纽的 B→A→C、C→A→B 和 A→B/C；断网/重连、
枢纽关闭以及 IPv4/IPv6 地址状态；同时回归 r11-85 的网络监听和发射后接收保护。
恢复旧版使用原 r11-85 OTA，配置迁移和旧四槽键的回退范围仍按 network-upgrades.md。
