# r11-95 射频接收转网络降噪候选

基线为 r11-94（`b0252a9`）。此候选验证一个方向，从 SA818 接收的 PCM 进入公网直连或 MQTT 网络前做轻度频谱降噪。接收板的网页中，简洁版入口为「音频调校 → 降噪」，详细版有「射频接收 → 网络降噪」卡片。公网直连和 MQTT 分开保存，均默认关闭。当前话段使用开始时的设置。

算法采用 SpeexDSP 1.2.1 定点实现，16 kHz 单声道、10 ms（160 个样本）、最大噪声衰减参数 −6 dB。初始化只在启用或读取已启用配置时进行。工作区和初始历史快照在 PSRAM，监视任务按话段恢复历史。每次 FFT 前后测耗时，超过 2.5 ms 时保留未提交的原 PCM，并在该话段剩余时间使用原声。下一话段重新尝试。缺少 PSRAM 工作区时整个话段走原声。

`GET /api/rf_denoise` 返回两个保存状态、正在应用降噪的模式、状态枚举、每次启动以来的处理帧数、单帧最大耗时、超时计数及已分配的 PSRAM 字节。状态 0～4 依次为关闭、等待下一话段、正在降噪、内存不足旁路、超时旁路。网页在卡片可见时刷新数据。POST 需要该手台的 `X-ORL-Device`，请求体携带 `mode`（1 公网直连、2 MQTT）、布尔值 `expected` 与 `enabled`。对同一模式的并发变更按已保存状态校验。

滤波使用桥接已通过 COS 和接收保护的 PCM 副本。正常 COS 关闭时排出最后有效样本，再走原来的板载尾音与网络结束事件。保护、改房间、收听停止或桥接释放会弃掉尚未提交的算法历史。实际提交前再次检查流代次、网络模式和房间、信道、静噪保护及半双工状态。编解码、射频参数与 APP 音频协议沿用 r11-94。

## 用户实测

1. 在一台音频功能正常的板上，用网页 OTA 上传候选应用镜像。用 r11-94 对端接收即可。记录双方版本、实际模式、固定增益、接收电平及接收保护设置。
2. 选好桥接信道，在 RF 输入侧使用相同内容与接收条件做两轮录音。先关闭对应的降噪开关，再开启。复测轻声、中文声母、呼号、数字、短按和连续话段。观察末字、是否各有一次尾音及是否有新增释放延迟。
3. 在公网直连和 MQTT 分别重复。记录网页卡片或 `/api/rf_denoise` 的处理帧、最大单帧耗时和超时计数。只有处理帧增长且未反复旁路的段落才用于判断降噪本身的听感。
4. 同时收听本机、APP 或网页，核对打开转发降噪时的其他输出。确认长期运行、重启保存和两种网络模式独立设置。
5. 如音质或连续性退化，可关闭当前模式的降噪。需要回退固件时，使用升级前留存的实际运行应用，或先前确认匹配设备的 r11-94 OTA。下载给测版本的 full 镜像用于独立工具 USB 保留模式，OTA 使用应用镜像。
