# r11-103 全链路异步降噪

## 固件实现

手台射频发射、本机收听、射频转网络、网络发话、网络收听和网络转模拟桥接全部使用相同的 PCM 适配器。每条路径保留有界原声和结果队列。一个优先级低于现有采集和网络播放任务的后台任务处理 SpeexDSP，并按截止时间选择各路径待办项。30 ms PCM 提前量供处理使用，DAC 路径原有提前量为 20 ms。

到交付时刻，已完成的结果按话段和样本位置对齐。处理迟到、队列满或前帧缺失时按原位置用原声。原声切换用 5 ms 平滑过渡，三个连续结果就绪后渐变回到降噪。新话段不会读到旧话段的 PCM，迟到结果直接舍弃。末帧只交付有效 PCM，收尾时已准备好的样本按时排空。射频键控、网络结束标记、尾音和 I2S 写入由音频链路负责。

公网直连和 MQTT 分别维护网发及射频转发状态。运行详情显示当前或最近一段的输入、降噪／原声帧数、队列满和恢复次数，另显示累计处理经过时间、排队峰值与 I2S 计数。

## 真机复测

1. 用 `heimao-app-OTA-r11-103.bin` 升级测试设备，先记录运行详情的累计计数。
2. 让同一段射频来话同时送本机喇叭和网络端，两条降噪各开启。持续约 30 秒，核对两端听感、首尾、I2S 欠载及各路输出覆盖率，再测数次短按。
3. 在公网直连和 MQTT 下分别测试网络来话到模拟桥接。实际射频对端听首尾和尾音，观察是否解键及是否有重复。再回归仅网发、网发与本机射频同开，以及桥接关闭时的本机守听。
4. 运行详情里的「迟到」累计值反映截止点没有降噪结果。优先核对本话段原声帧和恢复数，以及 I2S 欠载增量。

软件验收使用真实 SpeexDSP 和生产适配器，离线模拟慢帧、队列满、取消与换源。真实硬件任务余量、额外端到端延时、通联听感由用户验证。候选包包含 r11-102 回退 OTA 和完整 BIN。
