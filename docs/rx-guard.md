# 发射后接收抑制（固定时间）

适用：固件 r11-84 起，配套 APP 1.2.14（versionCode 26）起。功能默认关闭。

用于两台智能手台把模拟中继 A、B 通过公网直连或 MQTT 网络中继互通：

```text
模拟中继 A ⇄ 智能手台 A ⇄ 网络 ⇄ 智能手台 B ⇄ 模拟中继 B
```

手台向本地模拟中继发射结束后，中继可能继续发出拖尾载波、提示音。立即恢复
射频接收并回传网络可能让两侧反复触发。接收抑制为每台手台设置一个固定保护窗口。
时间到后立即恢复，不等待 COS 关闭；这就是固定时间方案 A。

## 设置

网页在两种网络模式各自的模拟桥接卡片下；APP 在工作模式页的模拟桥接区域下。
配置保存在手台，网页与 APP 共用，公网直连、网络中继分别保存。

| 设置 | 范围与默认值 |
|---|---|
| 启用 | 默认关闭，升级后不改变原来的接收行为 |
| 保护时间 | 1–60000 毫秒，步进 1 毫秒；初始值 2000 毫秒 |
| 时间单位 | 秒（最多三位小数）或整数毫秒，切换不丢精度 |
| 微调步进 | 1 / 10 / 100 / 1000 毫秒，仅调整编辑器操作步长 |
| 快速填入 | 100 / 250 / 500 / 1000 / 2000 / 3000 / 5000 / 10000 毫秒，仍须保存 |
| 触发来源 | 网络桥接、APP/网页 PTT、本机话筒/实体 PTT，默认全选 |
| 屏蔽出口 | 射频→网络转发、APP/网页收听、本机喇叭，默认全选 |

触发来源与屏蔽出口各须至少选择一项。要防止中继拖尾回传，须选中“射频→网络转发”。
本机话筒/实体 PTT 指固件 TALK 发射路径，也包含该路径的串口射频测试。
编辑器的单位、微调步进是界面偏好，不写入手台。

只有本机处于网络模式且模拟桥接就绪时才生效；本地电台模式、桥接关闭或网络引擎
停止时不生效。仅通过网络发送、没有实际键控本机射频时，不触发保护。

## 运行规则

- 从实际射频 PTT 释放时开始，不从 APP 松键、网络结束包或尾音开始时计算。
  本机尾音还在射频发射时，倒计时尚未开始。
- 保护仅屏蔽射频来源的音频出口。网络收包、连接保活、网络语音转射频、发送尾音
  和本地试听不被计时器阻塞；原始 COS/静噪读数保留供诊断。
- 被屏蔽的音频直接丢弃。APP/网页接收环在门控关闭时清空，不在到期后补播。
  关闭 RF→网络流时只发送结束标记，不因保护额外生成一次尾音。
- 到期恢复当前收到的音频，即使 COS 仍开也恢复；不会等待下一次载波。
- 再次实际发射时取消旧计时，从最后一次发射结束重新计算。
- 正常释放、强制释放和 PTT 看门狗释放共用实际射频输出边沿。
- 一组模式配置作为单个 NVS 数据更新保存；保存失败不更新运行配置。
  关闭保护保存成功后立即取消倒计时。其余修改不改变正在执行的时间和出口范围，
  用于下一次发射结束。
- 切模式、桥接停用、引擎停止会取消旧保护；重启只恢复设置，不恢复旧计时。

**1 毫秒是配置分辨率，不是硬件恢复时间保证。** 音频按块处理，实际恢复受 ADC/I2S
缓冲和任务调度影响。在保护窗口内开始处理的块整体丢弃；界面显示的是轮询采样的
近似剩余时间。此功能不执行延时等待，不增加音频缓存。

时间过短可能漏过拖尾；过长会丢失本地快速接话的开头。两端按各自中继实际情况调整。
默认 2 秒只是编辑初值，不代表已实测适合任何特定中继。

## API

沿用 `/api/set` 的字符串键值协议，推荐 JSON POST：

```json
{"k":"rx_guard_p2p","v":"1,1234,7,7"}
```

网络中继用 `rx_guard_relay`。值依次是：`启用,毫秒,触发来源位掩码,屏蔽出口位掩码`。

| 位 | 触发来源 | 屏蔽出口 |
|---|---|---|
| 1 | 网络桥接射频发射 | RF→网络转发 |
| 2 | APP/网页 SDR 射频发射 | APP/网页 RF 收听 |
| 4 | TALK 射频发射 | 本机 RF 喇叭 |

启用仅接受 0/1，毫秒为 1–60000，两个掩码均为 1–7。拒绝小数、负数、溢出、
尾随字符、额外字段和空字段。设置整组原子保存，不按多个请求逐项更新。

`GET /api/status` 新增：

```json
"rx_guard": {
  "version": 1,
  "p2p": {"en": 1, "ms": 1234, "sources": 7, "outputs": 7},
  "relay": {"en": 0, "ms": 2000, "sources": 7, "outputs": 7},
  "blocked": 7,
  "remaining_ms": 1200
}
```

`blocked` 表示当前被屏蔽的出口，0 表示未在保护中。旧固件缺少 `rx_guard.version=1`
时，APP 与网页不提供可操作的新设置。NVS 键 `orl/rxguard1` 为带版本的数据块，
与原有 RF/Wi-Fi/信道配置独立。

## 验证

离线回归：`python tools/test_rx_guard.py`、`python tools/test_bridge_edges.py`、
`node tools/test_rx_guard_panel.js`；APP `RxGuardRulesTest` 覆盖时间精度、严格校验、
整组编码、独立模式和旧固件兼容。

上板验收：两端分别测试 P2P/MQTT、正常松键/再次发射、1/37/1234/60000 毫秒、
模式切换、重启配置、保护期间新来话，以及不同出口与触发来源的组合。
确认拖尾不再反向触发，并调整到不会明显吞掉快速接话的时间。
构建和主机测试不代表已完成实板、手机听感或模拟中继互通验收。
