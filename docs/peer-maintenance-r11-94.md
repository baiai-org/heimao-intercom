# r11-94 测试候选：对端名称与设备维护

配套APP 1.2.19（31），独立刷机工具1.1.5。正式公开版仍为r11-93；本文件描述测试候选，实际构建提交、哈希、离线验证及待实测范围看候选BUILD-INFO和验证记录。未加入降噪。

## 公网直连名称

- 添加时可填中文备注，已有对端直接“改名”；最多24个Unicode码点、96个UTF-8字节，禁止控制字符/无效编码，留空恢复默认短名。
- 名称保存在设备的独立版本化`hm_peers/labels1`数据中；旧`orl/np_state1`的对端、拒绝记录与16对端容量保持。名称不参与通信和身份判断，不改远端公共名称。
- 通过稳定对端ID操作，使用全局名称revision检测并发修改。未识别时绑定完整端点，识别后关联MAC；同一IP多个未知对端优先完整端点匹配，不对有歧义的NAT端口变化猜测归属。
- 备注记录容量16项，按当前对端回收已离开对端的备注名额。重命名不执行重连/删除；保存失败保留旧值。添加对端与备注为独立持久化步骤，若只有对端添加成功，API与界面明确报告部分成功并保留草稿。
- 网页/APP同时显示名称和地址；旧APP可读取新的`name`，新APP连接旧固件时保留原7字节添加方式。

## 手动及定时重启

网页页头“重启本机”适用于所有页面及双布局；APP设备维护页也提供入口。确认后，设备在回复后安排整机软重启，先释放PTT并锁止重启前的新发射，再停音频。保存的模式、桥接、射频和网络设置不被重写为默认值。

维护设置保存在独立`hm_maint/config1`，具备revision检查及失败回滚。定时重启默认关闭，开启默认24小时，可填1～168小时。保存后及每次启动重新计时；关闭/重新设置取消旧待执行任务。到期等待连续空闲60秒，忙碌时持续延后。PTT、COS与话段边沿记录时间，短于主循环周期的活动也会重置空闲期；执行前再次检查。

手动操作校验设备身份与当前boot_id，旧启动周期的重启请求不能重放到新周期。页面区分“请求已接受”和“设备已经同身份、新boot_id上线”，60秒内未确认只提示重查，不自动重发重启指令。手动重启不依赖自动维护配置读取成功；当前上传、转换及关键存储写入会阻止安排重启。

## 资源维护

自动维护默认开启，每5分钟检查一次，共享音频工作区需连续空闲60秒；“立即检查并回收”采用相同空闲判断。检查无可回收资源时如实显示“无需清理”。

- P2P回收已排空且空闲的抖动缓冲与解码器，保留地址、名称、连接状态、拒绝决定和近期话段/序号历史。新包到来后按需重新分配。
- MQTT回收符合条件的解码器、复位已结束流的临时播放状态，保留活动引擎的固定工作容量及发送者顺序历史，不重启MQTT连接。
- 网页/APP音频会话已关闭时回收共享HTTP音频工作区。SDR基础环、尾音预加载、正常任务栈、日志及事件环保持。
- 保留原有SDR孤儿会话、MP3任务取消等既有时限，不将即时释放推迟到5分钟检查。
- 信道临时文件只在HTTP写入启动前检查；有效正式文件优先，正式文件缺失/无效时尝试恢复有效临时副本，提升失败保留唯一可恢复文件。不做周期扫盘、全擦NVS或自动清除崩溃证据。
- 显示检查次数、延后次数、最近检查的启动内时间、释放的缓冲字节数、解码器数量，以及内部内存/最大连续块/PSRAM。释放字节数只计已知缓冲，不能当作运行中总空闲内存增量。

本功能不证明用户原先反馈的缓存故障已定位；仍需结合诊断与长期运行观察。自动维护与定时重启独立控制，不因“内存低”自行重启。

## API与兼容

`GET /api/device`通过`capabilities.maintenance:1`、`peer_labels:1`协商；`np2p`状态增加`labels_version`、`labels_ready`、`label_revision`，每行增加稳定`id`及`custom_label`。

新增写接口均复用现有串行写锁，并要求`X-ORL-Device`匹配当前设备；不重新引入已移除的控制租约。

- `GET /api/maintenance`：维护设置与运行状态，含`device_id`和`boot_id`。计时以启动内单调时间为准。
- `POST /api/maintenance`：`{"op":"set","revision":0,"cleanup_enabled":true,"restart_enabled":false,"restart_hours":24}`；开关必须是JSON布尔，小时必须是1～168整数。
- 同接口`{"op":"cleanup"}`请求回收；`{"op":"reboot","boot_id":"当前值"}`请求手动重启。
- `POST /api/np2p/peer`：`{"op":"rename","id":"当前对端ID","name":"备注","revision":0}`，或`{"op":"add","name":"备注","address":"[IPv6]:端口","restore":true,"revision":0}`。恢复被拒绝地址必须由用户明确确认。

400表示无效参数，409表示版本/身份/忙闲冲突，503表示未确认执行或保存成功。对端部分添加失败时另含`peer_added:true`，客户端不得自动重放写操作。

## 验证与使用边界

离线回归覆盖真实C函数、UTF-8和16对端边界、NVS失败/重载、完整端点与MAC绑定、忙闲/取消/长时间计时、PTT重启锁止、临时文件恢复、过期缓冲与顺序历史、HTTP身份及JSON边界。网页以真实HTML/JS及模拟HTTP验证桌面、手机、双布局、草稿、保存失败和重启确认；这些不代替实板验证。

用户实测需检查：名称及开关断电保存、两种网络模式通联、手动重启后配置/连接恢复、定时到期与忙碌延后、缓存回收后首尾音/短按/尾音及长稳。软件计时快进测试不等同已经运行24小时。

OTA使用应用BIN，USB保留模式使用独立full BIN及无内嵌固件工具。现有OTA过程可能切换到本地模式，升级后先核对所需模式和桥接开关；本版手动/定时重启不主动改这些已保存值。新配置独立存储，回退r11-93会忽略新增备注和维护设置，原对端与拒绝格式不变；实机回退前仍需先备份即时配置和运行应用。
