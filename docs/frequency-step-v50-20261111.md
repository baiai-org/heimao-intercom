# 示例设备V50 频率步进实板调试记录

日期：2026-11-11，Asia/Shanghai。对象 device_id：示例设备V50，VHF。

结论：这块模块的设置接口并非只能使用 12.5 kHz 网格。相对 144.7500 MHz 原接收频率，
1、2.5、5 kHz 偏移已经真实设置成功，并由模块 UART 的 AT+DMOREADGROUP 回读一致。
1 kHz 和 5 kHz 同时在 12.5/25 kHz 带宽下通过；2.5 kHz 只测了 25 kHz 带宽。
目前固件、网页与 APP 的 12.5 kHz 输入校验是软件层面的额外限制，可以据此设计更小步进，
但本轮没有永久修改生产固件的校验或把板子留在“解锁”状态。

这是串口设置和模块参数回读证据。没有连接频率计/频谱仪/信号发生器，没有实际射频发射，
不能把回读一致解释为已量得载频或接收中心频率，也不能外推到 UHF 模块和全部频点。

## 方法与保护

原机为 r11-85，完整应用回读 1,827,520 字节，SHA256
`2a396e4d301191233efa943ed0a5924fd5c232b916efd7c5ffa8c17790967f81`，与原测试包完全一致。
正常 /api/set 对 144.8000/144.7550 返回 `invalid TX/RX frequencies (12.5k grid)`，没有到达模块。

因此临时 OTA 了专用 `r11-85-freqdiag-v50`。本地诊断分支为 debug/frequency-step-v50-20261111，
源码提交 623b8c3，专用接口按设备身份和本地私有口令限制，未作为通用原始 AT 接口发布。
诊断映像已完整回读核验。诊断主机测试覆盖锁、PTT 禁发、原参数恢复、拒绝、超时、重试和失败保持禁发；
固件构建成功，HTTP 诊断处理函数静态帧 1488 B，状态函数 4528 B，均低于 6144 B 上限。

模块真实版本响应为 `+VERSION:SA818S_V1.2`。原模块组参数：
`+DMOREADGROUP:1,144.8000,144.7500,0008,3,0008`。
全部试验固定 TX 144.8000，不键控 PTT，只临时改变 RX 和指定试验的带宽。
每轮在同一模块锁内进行“读原值 → 下发试验值 → 模块回读 → 下发原值 → 模块再次回读”，
并核对原组参数完全恢复；不把试验参数写入 ESP32 NVS。
模块命令自身可能保存其设置，故每轮均明确重新下发原值，而不是只恢复网页显示。

全部 15 轮：PTT GPIO 前后均为 1（释放），发射计数前后均为 0，受保护配置一致；
诊断阶段活动采样属于同一个 boot_id，没有被中途重启掩盖失败。

## 精细步进和 6.25 kHz 的边界

- 0.5 kHz 偏移的单个宽带样例回读一致，未据此宣布全频段最小分辨率。
- 100 Hz 相关输入不能只看成功 ACK：144.7501 回读 144.7500；144.7502 回读 144.7501。
  144.7562 回读 144.7561；144.7563 回读 144.7562。这说明存在内部量化或回读格式截断，
  本轮未测射频，不能指定其真实最小硬件频率步进。
- 直接输入精确的 144.75625（6.25 kHz 偏移、五位小数），在两种带宽均收到 `+DMOSETGROUP:1`。
  仅给已通过的 144.7550、144.7625 末尾补一个 0，变成五位小数，同样被拒绝。
  因此存在串口频率字段格式限制，不能将五位小数的拒绝直接归结为 PLL 必然不支持 6.25 kHz。
- 用 144.7563 近似代替 144.75625，会回读 144.7562，不能把这种近似和回读偏差包装为精确解锁。

后续软件方案可以先考虑已验证设置/回读的 1、2.5、5 kHz 输入或编辑步长，同时保留模块频段、
PTT 与 ACK 保护，增加真实模块回读核对。6.25 kHz 及更细分辨率应另用仪器确认后再决定转换规则。
