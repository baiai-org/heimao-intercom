# r11-91：网络收包与射频键控顺序修正

基础为 r11-90（971f474）；用户授权修正并离线复测，不授权本轮设备访问或部署。

## 行为

- 公网直连与MQTT不再把每个收到的PTT位直接写入共享发射请求；先检查话段、序号、重复和播放头，再提交接收状态。
- 公网直连跟随当前可播放发送者，MQTT跟随当前选择的音频源。无关来源的结束包不能停止当前来源；被拒绝的包不转发Hub、不延长PTT超时。
- 缓存500毫秒空闲复位不再抹掉话段顺序判断。短话段已结束时不继续等待六帧预充；从本话段首帧排空后再释放，保留原250毫秒保持和2秒丢结束包兜底。
- 现有发射后接收保护的时间、开关和出口含义不变；没有新增全局禁发或COS等待。

## 报文兼容

不改变报文长度、Opus参数、房间、PSK或语音载荷位置。新增flags bit5标识可选的16位话段标记：公网直连复用音频包中原nat_hint/ver两字节（大端）；MQTT复用原reserved字段，沿用原头部字节序。控制包NAT提示不变。旧接收端忽略这些字段，新接收端继续接受未标记的旧端。

新发送端在网络引擎启动时随机初始化标记，每次新的发话递增并跳过0；接收端保留最近16个退役标记。它是有限窗口的时序保护，不是认证或任意延迟下的防重放协议。16位标记在重启后有小概率与近期记录相撞，遇到时后续新一轮话段可恢复；不能据此宣称绝对无丢话。

旧发送端没有话段身份，重启归零只能推断：超过2秒未有有效新数据后，需三个连续递增的低序号ON包才能恢复，可能丢失最初约40毫秒。一次旧ON不能单独解除结束状态。已识别的新端不能被未标记数据降级；有意回退旧发送端时，接收端需要停开网络模式以清除本轮顺序状态。完整增强效果需要两端均运行新固件。

MQTT同时保留16个来源的顺序状态；未用或超过90秒未有有效新包的槽可回收，满表拒绝新增来源，不淘汰仍活跃的来源。公网直连仍为原16对端容量。
