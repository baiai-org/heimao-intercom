# 公网直连删除后持久拒绝（r11-88 / APP 1.2.18）

用户确认方案 A 后实施；测试候选，实板验收另记。本功能只影响公网直连，不改变 MQTT 中继、射频参数或音频处理。

## 行为

- 删除对端会同时删除连接地址并持久保存拒绝记录。B 当时离线、超过五分钟、A/B 重启、B 再次手动添加 A，均不能解除 A 的本地拒绝。
- 已识别的对端按协议发送者 MAC 拒绝；更换公网 IP、NAT 端口、IPv4/IPv6 不改变这一决定。这里的身份用于连接管理，不是新增的设备密码或证书。
- 身份未知的旧条目只能按完整 IP 与端口拒绝。不会拒绝同一公网 IP 下的所有设备；端口/IP 改变后这类记录无法识别原设备，网页和 APP 明确显示限制。
- 未被拒绝的新设备仍沿用原有单边填写地址、另一端自动接入的方式。正常暂时断线仍自动重连。
- 拒绝原始发送者的检查先于创建对端、音频缓冲、来话 PTT 与 Hub 转发。删除经 Hub 发现的成员不会向共享 Hub 发送 BYE，也不会拦截其他成员。
- 已拒绝设备的直接 KNOCK 会收到限速的兼容 BYE，让在线的旧固件尽力清理旧地址；本地拒绝完全不依赖通知是否送达。旧版远端的“手动添加”标记不能覆盖本地决定。

## 恢复与界面

网页与 APP 公网直连页显示已拒绝数量，提供“管理已拒绝设备”。列表最多 64 条，独立于 16 个活动对端名额；不按时间自动过期，也不静默覆盖旧记录。

恢复有两种入口：

1. 在 A 的已拒绝列表确认“解除拒绝”。B 随后可主动连接；解除本身不替 A 新建地址。
2. 在 A 主动添加地址并确认“如果此地址曾被拒绝，将解除对应拒绝并恢复连接”。只恢复与该完整地址匹配的记录；B 地址已变化时，先通过已拒绝列表解除原身份记录。

老 APP 的普通添加接口不能隐式解除新固件的拒绝；使用网页或配套 APP 完成恢复。老固件不支持此能力时，新 APP 隐藏管理入口并使用原添加接口。

## 保存与兼容

- 新 NVS 键 `orl/np_state1`：一个版本化 blob 同时保存活动地址、活动对端 MAC 和拒绝列表。每条固定 33 字节，上限 2644 字节；快照和编码临时缓冲放 PSRAM。
- 首次升级读取原 v3/v2/v1 地址，未知 MAC 留空；以后学习到身份后会随配置保存。旧地址键保留供主动回退，新状态存在后不再读取旧键覆盖它。
- 删除先确认新状态保存成功，再清理运行对端与通知远端。保存失败会返回错误、恢复运行记录，不显示成功；添加/解除失败同样回滚本轮运行修改。
- 列表满时拒绝新增删除操作并提示用户处理列表，不移除其他拒绝。新策略读取失败时停止接纳连接并显示错误，不回退成“没有拒绝记录”；重启重试或显式恢复出厂另作处理。
- 恢复出厂会清空连接与拒绝记录。降级到 r11-87 或更早版本不执行新拒绝规则，还可能加载旧地址；不要把降级作为保留拒绝规则的方法。

## 接口

- `/api/status.np2p` 新增 `access_version:1`、`access_ready`、`denied_count`、`denied_limit`。已有 `drops.tomb` 计数现在包括持久拒绝；`save_pending` 仍表示待保存。
- `GET /api/np2p/denied` 返回 `{count,limit,ready,entries:[{id,name,ip,port,identity}]}`，单独 16 KiB PSRAM 响应，不挤占主状态列表。
- 原 `np2p_peer_del` 变为删除并持久拒绝。`np2p_peer_add` 不解除拒绝。
- 新 `np2p_peer_restore` 与添加参数相同，只用于本机确认后的恢复添加。
- 新 `np2p_unblock` 使用列表稳定 `id`，避免按列表位置解除错误记录。写入仍走原设备身份与控制租约门禁。

## 验收

离线主机测试使用实际策略编解码和生产接入/保存/删除/恢复函数：五分钟与重启、已保存 MAC、地址变化、远端手动标记、共享 IP、Hub 原始身份、旧地址范围、满表、保存失败回滚、损坏状态、64 条列表边界及 16 对端回归。

网页用实际面板加本地模拟 HTTP 检查管理、确认、失败提示、桌面/手机尺寸、旧固件兼容，并回归接收保护、频率步进和 Hub 页面。APP 构建、单测、Lint 与固件最终构建结果看候选 BUILD-INFO。

仍需两台实板：B 断电→A 删除→B 上线；双方断电后重试；B 更换网络后重试；A 主动恢复；经 Hub 的成员拒绝与其他成员通联。没有以主机模拟代替真实断电/NVS 验收。
