# r11-92：中继互联开头音频与排空时序

基于r11-91编译输入eff88a4及说明提交1d52b15。用户授权按研究建议实施；本轮不访问设备或部署。

## 修正

- 网络注入每次实际PTT输出置为发射后单独计时300ms；其间不消费首PCM。网络抖动缓存与300ms音频预充仍保留，准备与预充重叠进行，不将每种等待机械相加。
- 网络输入结束后，小于4800点的短话段也可以启动；最后一个插值采样点精确排出，不再以“残留1点+已预充”状态跨越到下一轮。下一轮重新预充。
- 网络生产者报告当前发送者/PTT及尚未解码的数据，PCM环与最后一次I2S写入均排空后才开始原250ms发射保持。完成的话段如DAC停滞，2秒排空上限会丢弃滞留数据并释放；不会无限维持发射。
- 播放任务先更新键控/提前时间，再注入PCM。环空间不足时不取走下一个网络音频块；非monitor的直接播放分支也在准备完成前保留网络播放头。停止时仅释放NETWORK所有权，取消自己的PCM，不清除SDR。
- 喇叭防爆音仅作用于最终RF喇叭副本；RF→网络及RF→APP/网页的音频不再被25ms防爆音清零。既有滤波、静噪判定、EQ、固定增益和动态处理约束不变。
- 默认硬件COS路径保留确认前一块PCM，在COS确认后按顺序送入网络/手机。捕获时与转发时的保护掩码同时生效；本机TX、试听/注入、旧候选、模式变化都不能回放该块。软件音频推断COS路径不增加预留。
- 当前播放流中已经接收、尚未播放的数据，不因500ms无新包而被清空。仍保留原容量和溢出追赶策略；同一未结束话段的迟到结束包不丢弃待播数据。公网直连不因此复活超过原新鲜窗口的未选中旧来源。

保留r11-91按来源/话段/序号处理PTT、退役标记和旧端兼容规则。没有增加全局禁发或等待COS关闭，也不改变用户接收保护时间、出口、频率、亚音或功率。

## 范围与取舍

300ms是本版固定的软件发射提前时间，源自已有预充预算，并非对任意中继的实测最优值。实际载波、亚音译码与接收打开还需仪器/现场确认；芯片内部尚未输出的音频无法通过软件恢复。

最后I2S写完成表示驱动写调用完成，保留250ms保持时间；不是逐样本实际射频测量。网络保持、buffer及超时均为非阻塞状态检查，没有在音频任务中sleep等待。

APP未改；正常monitor网络监听分流仍在射频增益和注入处理之前。没有生成新APK。r11-90与r11-91的原冻结输入和正式r11-89产品不覆盖。
