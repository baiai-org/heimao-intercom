# r11-93：内存、RF配置与面板可靠性

基于 r11-92；用户批准先处理自查中有证据支持的问题。此文描述实现及验证入口，最终构建提交、摘要、结果和未验证范围以独立候选中的 BUILD-INFO / validation 为准。没有自动部署设备。

## 内部内存与HTTPS

- 移除24 KiB常驻MP3任务栈。转换任务通过 xTaskCreateWithCaps 使用临时PSRAM栈，仅解码、下混和重采样；文件/NVS持久化由等待完成的内部栈调用方执行。
- 每个转换任务单独完成信号量和双引用计数，覆盖先完成、正常等待、超时、任务创建失败及分配失败。超时返回失败并取消后台持久化；后续清理完成前保持busy。WAV/MP3上传共用互斥忙标记。
- 10 KiB网页音频共享工作区在持有既有工作锁时按需分配到PSRAM。保留16 KiB音频注入环容量和原首尾保护，不直接迁移临界音频环或缩小任务栈。
- SDK清理补丁仅生成构建副本，原SDK不变。tools/patch_https_server.py检查规范换行后的完整源SHA256，只修复“握手成功、transport_ctx分配失败”时遗漏TLS释放的分支。生成来源记录位于build/heimao-patches，见firmware/patches/https-context-cleanup.md。

静态移除对象的大小不等于实机空闲内存必然增长值；新有界诊断也有少量占用。最终ELF布局和实际运行值分别验收。TLS会话上限、证书校验和协议安全设置不变。

## RF配置事务与恢复

- 单项HTTP/实体/控制台操作通过字段掩码在同一配置锁内合并到最新保存配置，再完成UART应答和持久化。不同字段不会互相覆盖；显式设置同值也保留该字段的写入意图。完整信道调用仍明确替换整套参数。
- 保持历史56字节NVS/信道结构。新增RF配置状态是运行时修订、应用阶段、错误、尝试数和恢复标记，不冒充模块参数硬件读回。
- 部分应用或保存失败继续阻止未经确认的RF发射，向调用方返回失败。后台恢复使用最后保存的完整配置，不静默关闭接收亚音，不将未保存的新参数当作已成功。
- 维护接回正常主循环。健康配置不在每次话后重调，避免重新调谐吞掉新呼叫开头。仅未确认配置在COS、网络音频、尾音和PTT均空闲后，等待1+10秒，再进行恢复；每代请求最多3次，无重复NVS写。失败保持可见，之后可由新的明确操作恢复。
- 配置开始与PTT控制同步，检查发射/所有者状态后才下发；UART等待期间不持有PTT控制锁，停止发射路径不会被整段AT事务阻塞。

实际CTCSS频率、DCS极性与接收解码仍需综测或已知正确设备确认。软件值显示、AT成功应答与射频实测是不同证据。

## 面板

- 所有通用只读请求共用2个执行槽，同路径合并；仪表单实例，radio元数据低频缓存并在RF修改时失效。PTT、设置、上传、音频不被通用读取逻辑重试。
- status/实时回应与radio模块错误分别处理。单个非心跳失败或渲染错误不导致全局离线；近期可达证据过期才显示断开，并保留上次状态时间。
- 保护模块始终有标题与加载状态；脚本失败可有限恢复，耗尽后可手动重试；重复挂载被阻止。字段暂缺保留草稿/最后值并禁用保存，不隐藏成空白或误称固件不支持。
- 亚音选择等待实际命令结果，替代固定1.5秒保护。列表未就绪时不提交空代码。就近显示每个方向的“正在应用/已确认并保存/未确认”，不把本地选择当作生效证据。

## 双关断声诊断

未增加200 ms结束确认窗或全局禁发，没有截尾、音频门限或动态降噪。新增64条有界事件历史，只记录时间、类别、来源和计数/话段标记，不保存PCM、SSID、broker账号或地址。

在“设备与维护”点击“导出连接与通联诊断”，读取 `/api/diagnostics`。接口包含内部内存当前/历史最小/最大连续块、分配失败回调计数、HTTPS错误与会话事件、RF软件应用状态及事件历史。计数回绕、日志窗口有限；不是无线电波形测量。

事件数组顺序：`[sequence, uptime_ms, kind, source, a, b]`。时间为32位毫秒，长期运行会回绕。

| kind | 内容 | source / a / b |
|---|---|---|
| 1 / 2 | PTT软件输出开启/释放 | PTT owner / token / machine=1或bridge=2 |
| 3 / 4 | 稳定硬件COS开启/关闭 | 网络模式 / GPIO / 0 |
| 5 / 6 | RF→网络话段开启/结束 | 网络模式 / 开始或结束累计数 / 结束时是否允许尾音 |
| 7 / 8 / 9 | 网络话段开启/结束/超时 | 网络模式 / epoch / sequence |
| 10 / 11 | 配置成功/失败 | 用户操作=0、空闲维护=1 / 应用阶段 / 配置修订 |

应用阶段：0未开始、1忙闲检查、2组参数、3音量、4滤波、5尾音、6持久化、7完整成功。阶段与`ready/error`共同判断。连接事件通过事件循环观测，不等于抓包或准确的所有浏览器socket时序。

## 验证入口

- `python tools/run_host_tests.py`：原主机回归及新增MP3生命周期、RF事务/空闲恢复、诊断JSON边界。
- `python tools/verify_https_cleanup.py --source <IDF>/components/esp_https_server/src/https_server.c`：实际SDK原函数经构建补丁后注入OOM，保留正常关闭/握手失败对照。
- `node tools/verify_resource_panel.cjs`：完整HTML与模拟设备，覆盖脚本首次失败、缺字段、慢响应、错误分类、布局草稿、亚音慢写及失败提示。只允许虚构设备域名。
- `tools/test_net_rx_order.py`、`tools/test_bridge_speech_prefix.py`：实际两引擎、PTT与voice函数的顺序/首尾/保护回归。
- `node tools/verify_panel_navigation.cjs`：六页与双布局的既有交互回归。

上述替身测试不能替代实机并发连接/音频、MP3上传、亚音测量、真实双端PTT和关断声验收。APP复用1.2.18，未新增APP功能或改变RF频率/滤波/增益的保存默认值。
