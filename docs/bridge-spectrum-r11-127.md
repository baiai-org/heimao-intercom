# 桥接与实时频谱连续性（r11-127）

r11-127 将网页实时频谱的数据来源与实际音频出口对齐，并取消音频任务与 HTTP 读取之间的阻塞争用。

## 自动来源

- 射频来话转发到 P2P 或 MQTT 时，取样点为桥接音频进入编码队列之后。
- P2P 或 MQTT 来话转发到射频时，取样点为桥接音频成功写入 I2S 之后，也就是实际送往 SA818 的 PCM。
- 桥接话段以方向和单调话段号标记。同一话段中的尾音继续沿用原来源，前一来源的历史频谱不会清空。
- 没有桥接话段时，自动选路继续按手台发话、远程发话、监听和喇叭等既有路径优先级工作。

## 旁路与缺口

音频生产者将固定大小块写入 64 块旁路队列，不等待 HTTP 或浏览器读取。HTTP 请求到达时，读者将可用块汇入 16 kHz 连续 PCM 环。队列满时只增加频谱缺样计数，不阻塞音频、网络编码或 PTT。

频谱协议 `APC3` 的 96 字节头包含：

- 音频路径、启动标识与单调世代；
- 桥接方向和话段号；
- 缺口逻辑起点、终点、样本数及原因；
- 旁路溢出、暂停、读端越界和租约恢复计数。

浏览器用 2,048 点 FFT、640 样本步进生成约 25 行/秒的频谱。真实缺口会切断当前 FFT 窗并保留时间轴位置，不补造 PCM。

## 验证边界

主机回归覆盖队列满、HTTP 批处理、声源切换、环形缓冲回绕和旧 `APC2`/旧 44 字节帧兼容。隔离 MQTT 实板测试覆盖 RF→网络 30 秒和网络→RF 34 秒，两个方向均为单话段、零桥接频谱缺口。该测试不代替真实 P2P 空口、远端听感或射频频率测量。
