# r11-87 / APP 1.2.17：1、2.5、5 kHz 综测候选

以用户反馈测试无问题的 r11-85 为基础，包含 r11-86 的音量键、切信道和 Hub 修复。
用户最终决定只开放 1、2.5、5 kHz，不包含 6.25 kHz。

## 本版行为

- 网页新增收发频率同时加减 1、2.5、5 kHz，保留 12.5、25 kHz 及 TX=RX。
  网页加减按钮会立即下发整组 TX/RX；手工编辑后点“立即下发”。
- APP 1.2.17 的收发频率编辑器增加 1、2.5、5 kHz 选择及加减按钮。
  APP 加减只修改草稿，点击保存后下发；既有包名和签名延续。
- `/api/radio` 新增 `freq_grid_hz:500`、`freq_decimals:4`；APP/网页未读到能力时按旧 12.5 kHz 校验。
  500 Hz 是 1/2.5/5/12.5 kHz 组合的共同设置网格，不是对模块最小硬件步进的测量结论。
- UART 仍采用四位小数 MHz，先从旧 float MHz 恢复到有效设置网格再格式化。
  不把 6.25 kHz 四舍五入成 6.2 或 6.3 kHz，6.25 kHz 和 100 Hz 输入会被拒绝。
- 频段范围、PTT 配置互锁、完整组参数 ACK、NVS 提交成功后才就绪的规则保持。
  模块拒绝/超时会显示失败并阻止射频键控；重新提交已知可用频率恢复。
- 信道库、桥接兼容检查与状态输出采用同一网格；NVS 原有 56 字节配置结构不变。
  “信道带宽 12.5/25 kHz”是接收/调制带宽，与此次频率调整步长独立。

## 实测依据与边界

2026-11-11 已对 示例设备V50（`示例设备V50`）的 VHF 模块
`+VERSION:SA818S_V1.2` 做过临时 RX 参数探测：1、2.5、5 kHz 偏移设置/直接 AT 回读一致，
其中 1/5 kHz 分别试过 12.5/25 kHz 带宽。6.25 kHz 五位小数字段被模块拒绝，100 Hz 有回读偏差。
该轮没有射频测量或 TX 小步进发射，已恢复原机 r11-85；记录见 `frequency-step-v50-20261111.md`。

本次 r11-87 只构建和出包，不连接实板或替用户刷机、发射。VHF/UHF 实际载频、
接收中心、频差、USB 刷写、真实手机和多台 Hub 通联由用户安装后验证。
状态页显示的是已保存且下发获 ACK 的配置，不是综测读数，也不是逐次 AT 直接回读。

## 综测建议

1. 用包内工具“保留配置刷机”，或用 OTA 应用 BIN 升级；APP 覆盖安装。
2. 先记录设备身份、频段、原信道/频率/亚音/功率/带宽及固件版本；选好本次仪器测试频率。
3. 发射测试先接妥额定功率匹配的 50 Ω 综测输入或假负载/衰减链路，确认仪器输入上限。
4. 从同一基准分别试 +1、+2.5、+5 kHz，每组后回基准，再试负方向；分开记录 12.5/25 kHz 带宽。
   网页快捷键同时移动 TX/RX；只改一侧时直接编辑对应输入框并提交整组。
5. 每项记录：请求 TX/RX、界面保存结果、实际载频、相对基准变化 Hz、绝对频差 Hz、功率、带宽、设备/模块型号。
   RX 中心频率另用综测信号源验证。不要仅凭保存成功或网页数字判断实际频率正确。
6. 模块拒绝时记录错误，重新提交原频率；不要把失败后沿用的旧载频算作新频率结果。

若回退 r11-85/r11-86，先将当前收发频率恢复到原 12.5 kHz 网格；
小步进信道可保留备份，但旧固件会把不兼容项禁用，不会自动变成近似频率。
本版仍待用户综测，不将离线验证写成射频验收。
